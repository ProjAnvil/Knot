# tools

Code generators for the `models` module. Both commands run from the repo
root; the Go workspace resolves the `models` module for them.

## Commands

### JSON Schema: `gen-schema`

Reflects over `models.KnotExportDocument` with
[invopop/jsonschema](https://github.com/invopop/jsonschema) (draft 2020-12)
and writes the golden schema to `models/schema/knot-v1.schema.json`:

```sh
go run ./tools/cmd/gen-schema
```

Post-processing applied by the generator:

- `$id` is pinned to
  `https://github.com/ProjAnvil/knot/models/schema/knot-v1.schema.json`.
- The root envelope properties are pinned as constants —
  `properties.format.const = "knot"` and `properties.version.const = 1` —
  using the same `models.WireFormat` / `models.WireVersion` constants the
  export builder writes, so schema and code cannot disagree.
- Properties backed by Go `*string` fields without `omitempty` (currently
  `KnotExportAPI.note` and `ParamNode.description`) are widened to
  `["string", "null"]`: the wire format always serializes such nil
  pointers as `null`, and the reflection output alone would wrongly reject
  Knot's own exports. The widening is derived by reflection over the same
  types, so future nullable fields are picked up automatically; the
  generator fails loudly if an expected property is missing.
- All nested types are referenced locally via `#/$defs/<Name>` (the
  reflector runs in anonymous mode; no per-type `$id`s). Because the
  widening step re-encodes the document generically, object keys are
  serialized in sorted order.

### TypeScript: `gen-ts`

Generates TypeScript declarations for the models root package
(`github.com/ProjAnvil/knot/models`, the `gormbind` subpackage is
intentionally excluded) with
[tygo](https://github.com/gzuidhof/tygo) and writes the golden to
`models/ts/index.d.ts`:

```sh
go run ./tools/cmd/gen-ts
```

Notes on the output:

- The file carries a `Code generated by tools/cmd/gen-ts. DO NOT EDIT.`
  header; the wrapper replaces tygo's own header line with it.
- `enum_style: union` is required because tygo's default `const` style
  emits typed const initializers, which are invalid in a `.d.ts` ambient
  context (tsc error TS1039).
- The `MarshalJSON` helpers in `models/api.go` and `models/parameter.go`
  use an unexported local alias (`type alias X`) so tygo does not export
  the helper type; an exported `type Alias` would collide as a duplicate
  TypeScript identifier across the two files.
- The generated interfaces follow the structs' `json` tags. `Group`,
  `API`, and `Parameter` have custom `MarshalJSON` methods that project
  `createdAt`/`updatedAt` as RFC 3339 strings; those runtime keys are not
  representable in the tag-derived declarations.
- tygo renders pointer fields as optional properties (`note?: string`)
  rather than `string | null`. For fields without `omitempty` (such as
  `KnotExportAPI.note` and `ParamNode.description`) the wire format always
  emits the key, with `null` for a nil pointer — the JSON Schema golden is
  widened accordingly (`["string", "null"]`), but the TS golden keeps
  tygo's optional rendering. This is inherent tygo behavior, not a bug in
  the generator.

## Why the goldens are committed

`models/schema/knot-v1.schema.json` and `models/ts/index.d.ts` are checked
in so consumers (frontend, MCP server, external validators) can use the
wire contract without a Go toolchain, and so every change to the contract
is visible in code review instead of silently regenerating.

## CI drift lock

The goldens must always match what the generators produce. CI (see the
`.github/workflows/ci.yml` drift job) regenerates both files and fails if
the working tree drifts:

```sh
go run ./tools/cmd/gen-schema
go run ./tools/cmd/gen-ts
git diff --exit-code -- models/schema models/ts
```

If CI fails on this check, a Go type changed without regenerating: run the
two commands above and commit the updated goldens together with the type
change. Generator output is deterministic (verified by double-run), so a
diff always means a real contract change.

## Dependencies

`tools/go.mod` pins exact versions: `github.com/invopop/jsonschema`
v0.14.0 and `github.com/gzuidhof/tygo` v0.2.21. Upgrading either can
change generated output; treat an upgrade as a contract-affecting change
(regenerate, review the diff, commit goldens in the same commit).
